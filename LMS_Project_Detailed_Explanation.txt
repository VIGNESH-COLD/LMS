1. PROJECT OVERVIEW
================================================================================

This is a full-stack Learning Management System (LMS) built for Rajalakshmi
Institute of Technology. It provides a web-based portal for managing academic
activities across three user roles:

  - ADMIN: Manages faculty, students, courses, timetables, calendar, deadlines
  - INSTRUCTOR (Faculty): Manages courses, quizzes, assignments, marks, materials
  - STUDENT: Views subjects, marks, assignments, achievements, events, timetable

The application uses a REST API architecture where:
  - Backend (Spring Boot) runs on http://localhost:8080
  - Frontend (React + Vite) runs on http://localhost:5173
  - Frontend communicates with backend via Axios HTTP client
  - Authentication uses JWT (JSON Web Tokens) - stateless, no server sessions

3. PROJECT ARCHITECTURE
================================================================================

The project follows a layered architecture:

FRONTEND (React SPA):
  User Browser --> React Components --> Axios API Service --> HTTP Requests

BACKEND (Spring Boot):
  HTTP Request --> Security Filter (JWT) --> Controller --> Service --> Repository --> MySQL

Data Flow Example (Student Login):
  1. User enters email/password on LoginPage.jsx
  2. Frontend calls authAPI.login() which sends POST /api/auth/login
  3. AuthController receives the request
  4. AuthService validates credentials using BCrypt
  5. JwtUtil generates a JWT token with userId, email, role
  6. Token is returned to frontend
  7. Frontend stores token in localStorage
  8. All future API calls include token in Authorization header
  9. JwtAuthFilter validates token on every request

4.1 CONFIGURATION LAYER (src/main/java/com/lms/config/)
--------------------------------------------------------------------------------

SecurityConfig.java
  - Configures Spring Security for the entire application
  - Disables CSRF (not needed for stateless JWT auth)
  - Enables CORS for frontend at localhost:5173
  - Sets session management to STATELESS (no server-side sessions)
  - Defines which URLs are public vs protected:
      PUBLIC (no login needed):
        /api/auth/** (login, forgot-password, change-password)
        GET /api/courses/** (browse courses)
        GET /api/course-materials/** (view materials)
        GET /api/files/** (download files)
        GET /api/events/** (view events)
        GET /api/announcements/** (view announcements)
        GET /api/semester-calendar/** (view calendar)
      ADMIN ONLY:
        /api/admin/** (all admin operations)
      AUTHENTICATED (any logged-in user):
        All other endpoints
  - Adds JwtAuthFilter before Spring's default authentication filter
  - Creates BCryptPasswordEncoder bean for password hashing

JwtUtil.java
  - Handles all JWT token operations
  - generateToken(email, role, userId): Creates a signed JWT containing:
      subject = user's email
      claim "role" = user's role (STUDENT/INSTRUCTOR/ADMIN)
      claim "userId" = user's database ID
      issuedAt = current time
      expiration = current time + 86400000ms (24 hours)
  - extractEmail(token): Reads the email from token
  - extractRole(token): Reads the role from token
  - extractUserId(token): Reads the userId from token
  - isTokenValid(token): Checks if token is valid and not expired
  - Uses HMAC-SHA256 signing with secret key from application.properties

JwtAuthFilter.java
  - Runs on EVERY HTTP request before it reaches any controller
  - Reads the "Authorization" header from the request
  - If header starts with "Bearer ", extracts the token
  - Validates the token using JwtUtil
  - If valid, creates a Spring Security Authentication object
  - Sets the authenticated user in SecurityContextHolder
  - Request then proceeds to the controller

CorsConfig.java
  - Allows cross-origin requests from http://localhost:5173
  - Permits all HTTP methods (GET, POST, PUT, DELETE, etc.)
  - Permits all headers
  - Allows credentials (cookies, auth headers)

4.2 MODEL LAYER - DATABASE ENTITIES (src/main/java/com/lms/model/)
--------------------------------------------------------------------------------

Each model class maps to a MySQL table. Spring JPA auto-creates tables.

User.java (Table: users)
  Fields: id, name, email (unique), password (hashed), role (STUDENT/INSTRUCTOR/ADMIN),
          avatar, department, section, rollNumber, year, semester, phoneNumber, createdAt
  Relations: One user can teach many courses (instructor), one user can have many enrollments

Role.java (Enum)
  Values: STUDENT, INSTRUCTOR, ADMIN

Course.java (Table: courses)
  Fields: id, title, description, thumbnail, instructor_id (FK to users), createdAt
  Relations: Has many modules, quizzes, assignments, enrollments

Module.java (Table: modules)
  Fields: id, title, description, orderIndex, course_id (FK to courses)
  Relations: Belongs to a course, has many materials

Material.java (Table: materials)
  Fields: id, title, type (VIDEO/DOCUMENT/LINK/FILE), url, fileName, fileSize, module_id
  Relations: Belongs to a module

Quiz.java (Table: quizzes)
  Fields: id, title, description, timeLimit, passingScore, maxAttempts, course_id, createdAt
  Relations: Belongs to a course, has many questions and submissions

Question.java (Table: questions)
  Fields: id, questionText, type (MCQ/TRUE_FALSE/SHORT_ANSWER), options (JSON), correctAnswer, points, quiz_id
  Relations: Belongs to a quiz

Assignment.java (Table: assignments)
  Fields: id, title, description, deadline, totalMarks, course_id, createdAt
  Relations: Belongs to a course, has many submissions

Submission.java (Table: submissions)
  Fields: id, student_id, quiz_id, assignment_id, answers (JSON), content, filePath,
          score, totalMarks, graded, feedback, submittedAt, gradedAt
  Relations: Belongs to a student, optionally to a quiz or assignment

Enrollment.java (Table: enrollments)
  Fields: id, student_id (FK), course_id (FK), enrolledAt
  Relations: Links a student to a course

InternalMark.java (Table: internal_marks)
  Fields: id, student_id, course_id, exam1, exam2, exam3, attendance, total
  Relations: Links a student's marks to a course

Achievement.java (Table: achievements)
  Fields: id, title, description, icon, badge (GOLD/SILVER/BRONZE), student_id, course_id, awardedAt
  Relations: Belongs to a student, optionally to a course

Event.java (Table: events)
  Fields: id, title, description, eventDate, location, type, createdBy (FK to users)

Announcement.java (Table: announcements)
  Fields: id, title, content, priority, targetRole, createdBy (FK), createdAt

Timetable.java (Table: timetables)
  Fields: id, course_id, dayOfWeek, startTime, endTime, room, building

SyllabusItem.java (Table: syllabus_items)
  Fields: id, course_id, topic, description, completed, completedDate, orderIndex

CourseMaterial.java (Table: course_materials)
  Fields: id, course_id, uploadedBy (FK), title, description, originalFileName,
          storedFileName, fileSize, fileType, uploadedAt

SemesterCalendar.java (Table: semester_calendars)
  Fields: id, title, description, date, type

MaterialType.java (Enum): VIDEO, DOCUMENT, LINK, FILE
QuestionType.java (Enum): MCQ, TRUE_FALSE, SHORT_ANSWER

ModuleRequest: title, description, orderIndex

MaterialResponse: id, title, type, url, fileName, fileSize
QuizRequest: title, description, courseId, timeLimit, passingScore, maxAttempts, questions

QuestionRequest: questionText, type, options, correctAnswer, points

AssignmentRequest: title, description, courseId, deadline, totalMarks
AssignmentResponse: id, title, description, courseId, courseTitle, deadline, totalMarks
QuizSubmissionRequest: quizId, answers (map of questionId to answer)
SubmissionResponse: id, studentName, quizTitle, assignmentTitle, score, totalMarks, graded, feedback, submittedAt
GradeRequest: score, feedback
AnalyticsResponse: contains maps of various analytics data

4.4 REPOSITORY LAYER (src/main/java/com/lms/repository/)
--------------------------------------------------------------------------------

Each repository extends JpaRepository which provides automatic CRUD operations:
  save(), findById(), findAll(), deleteById(), count()

Custom query methods (Spring Data derives SQL from method names):
  UserRepository: findByEmail(email), findByRole(role)
  CourseRepository: findByInstructorId(id), searchByTitleContaining(keyword)
  EnrollmentRepository: findByStudentId(id), findByCourseId(id), existsByStudentIdAndCourseId()
  QuizRepository: findByCourseId(id)
  AssignmentRepository: findByCourseId(id)
  SubmissionRepository: findByStudentId(id), findByQuizId(id), findByAssignmentId(id)
  InternalMarkRepository: findByStudentId(id), findByCourseId(id)
  AchievementRepository: findByStudentId(id)
  EventRepository: findByEventDateAfterOrderByEventDateAsc(now)
  AnnouncementRepository: findByTargetRoleOrTargetRole(role, "ALL")
  TimetableRepository: findByCourseId(id), findByDayOfWeek(day)
  SyllabusItemRepository: findByCourseIdOrderByOrderIndexAsc(id)
  CourseMaterialRepository: findByCourseId(id), findByUploadedById(id)
  SemesterCalendarRepository: findByDateAfterOrderByDateAsc(today)

4.5 SERVICE LAYER (src/main/java/com/lms/service/)
--------------------------------------------------------------------------------

Services contain the business logic. Each service is called by its controller.

AuthService:
  - login(): Finds user by email, verifies password with BCrypt, generates JWT
  - resetPassword(): Finds user by email, updates password
  - changePassword(): Verifies old password, then updates to new password
  - getUserByEmail(), getUserById(): Lookup helpers

AdminService:
  - getAllUsers(): Returns all users
  - getUsersByRole(): Filters users by role
  - createUser(): Creates a new user with BCrypt-hashed password
  - updateUser(): Updates user details (name, email, dept, section, etc.)
  - updateUserRole(): Changes a user's role
  - deleteUser(): Removes a user
  - allocateCourseToInstructor(): Assigns a course to a faculty member
  - extendDeadline(): Updates an assignment's deadline
  - getSystemStats(): Returns counts of students, instructors, courses, etc.

CourseService:
  - getAllCourses(): Returns all courses with module/student counts
  - getCourseById(): Returns single course with full details
  - getCoursesByInstructor(): Returns courses taught by a specific instructor
  - searchCourses(): Searches courses by keyword in title
  - createCourse(): Creates a new course assigned to the instructor
  - updateCourse(): Updates course title/description (only by owner)
  - deleteCourse(): Deletes course (only by owner)
  - addModule(): Adds a learning module to a course
  - deleteModule(): Removes a module
  - addMaterial(): Adds a material (video/doc/link) to a module
  - getModulesByCourse(): Returns all modules for a course

EnrollmentService:
  - enroll(): Enrolls a student in a course (checks for duplicates)
  - unenroll(): Removes enrollment
  - isEnrolled(): Checks if student is enrolled
  - getEnrollmentsByStudent(): Returns all enrollments for a student

QuizService:
  - createQuiz(): Creates quiz with questions (only instructors)
  - getQuizzesByCourse(): Returns all quizzes for a course
  - getQuizById(): Returns quiz details (hides answers for students)
  - deleteQuiz(): Removes a quiz (only by creator)

AssignmentService:
  - createAssignment(): Creates assignment with deadline and marks
  - getAssignmentsByCourse(): Returns assignments for a course
  - getAssignmentById(): Returns single assignment
  - deleteAssignment(): Removes assignment (only by creator)

SubmissionService:
  - submitQuiz(): Auto-grades quiz by comparing answers to correct answers
  - submitAssignment(): Saves student's assignment submission
  - gradeSubmission(): Instructor manually grades a submission
  - getSubmissionsByStudent(): Returns all submissions by a student
  - getSubmissionsByQuiz(): Returns all submissions for a quiz
  - getSubmissionsByAssignment(): Returns all submissions for an assignment

InternalMarkService:
  - getByStudent(): Returns all internal marks for a student
  - getByCourse(): Returns all marks for a course
  - uploadMark(): Creates/updates marks (exam1, exam2, exam3, attendance, total)
  - delete(): Removes a mark entry

AchievementService:
  - getByStudent(): Returns achievements earned by a student
  - create(): Awards an achievement (title, icon, badge level)
  - delete(): Removes an achievement

EventService:
  - getAll(): Returns all events
  - getUpcoming(): Returns events with date after now
  - create(): Creates new event (title, description, date, location, type)
  - delete(): Removes an event

AnnouncementService:
  - getAll(): Returns all announcements
  - getForRole(): Returns announcements targeting a specific role or "ALL"
  - create(): Creates announcement (title, content, priority, targetRole)
  - delete(): Removes an announcement

TimetableService:
  - getAll(): Returns all timetable entries
  - getByCourse(): Returns schedule for a specific course
  - getByDay(): Returns all classes on a specific day
  - create(): Creates a timetable entry (course, day, time, room, building)
  - delete(): Removes a timetable entry

SyllabusService:
  - getByCourse(): Returns syllabus topics for a course ordered by index
  - getProgress(): Returns percentage of completed topics
  - create(): Adds a syllabus topic
  - toggleComplete(): Marks a topic as completed/uncompleted
  - delete(): Removes a syllabus topic

CourseMaterialService:
  - uploadMaterial(): Saves file to disk + creates database record
  - getMaterialsByCourse(): Returns materials for a course
  - getMaterialsByInstructor(): Returns materials uploaded by an instructor
  - deleteMaterial(): Deletes file from disk + removes database record

SemesterCalendarService:
  - getAll(): Returns all calendar entries
  - getUpcoming(): Returns future calendar entries
  - create(): Creates calendar entry (title, date, type)
  - delete(): Removes a calendar entry

AnalyticsService:
  - getInstructorAnalytics(): Returns stats for an instructor's courses
  - getStudentAnalytics(): Returns stats for a student's performance

FileService:
  - uploadFile(): Saves a file to the uploads/ directory with unique name
  - downloadFile(): Reads and returns file bytes from disk

=== AuthController (/api/auth) ===

  Purpose: Authenticates a user and returns a JWT token
  Request Body: { "email": "user@example.com", "password": "password123" }

5. FRONTEND EXPLANATION
================================================================================

--------------------------------------------------------------------------------
5.1 ENTRY POINT & ROUTING (App.jsx, main.jsx)
--------------------------------------------------------------------------------

main.jsx:
  - Entry point of the React application
  - Wraps the app in BrowserRouter (for routing), AuthProvider (for auth state),
    and ThemeProvider (for dark/light mode)

App.jsx:
  - Defines all application routes using React Router
  - ProtectedRoute component: Checks if user is logged in and has correct role
    before allowing access. Redirects to /login if not authenticated.

  Routes:
    /               --> Redirects to /login
    /login          --> LoginPage (redirects to dashboard if already logged in)
    /admin          --> AdminDashboard (ADMIN only)
    /student        --> StudentDashboard (STUDENT only)
    /instructor     --> InstructorDashboard (INSTRUCTOR only)
    /course/:id     --> CoursePage (any authenticated user)
    /quiz/:id       --> QuizPage (STUDENT only)
    /results        --> ResultsPage (any authenticated user)
    /*              --> Redirects to /login (404 catch-all)

--------------------------------------------------------------------------------
5.2 CONTEXT PROVIDERS
--------------------------------------------------------------------------------

AuthContext.jsx:
  - Creates a React Context for authentication state
  - On app load, checks localStorage for saved token and user data
  - Provides: user (current user object), token, loading, login(), logout()
  - login(): Saves token + user to state and localStorage
  - logout(): Clears token + user from state and localStorage
  - Helper booleans: isInstructor, isStudent, isAdmin

ThemeContext.jsx:
  - Manages dark/light mode toggle
  - On load, checks localStorage for saved preference, defaults to system preference
  - Adds/removes "dark" class on <html> element
  - Provides: isDark (boolean), toggleTheme (function)

--------------------------------------------------------------------------------
5.3 API SERVICE LAYER (services/api.js)
--------------------------------------------------------------------------------

Creates an Axios instance with baseURL "/api" (proxied to localhost:8080 by Vite).

Request Interceptor: Automatically attaches JWT token from localStorage
to every request as "Authorization: Bearer <token>".

Response Interceptor: If any API returns 401 (Unauthorized), automatically
clears localStorage and redirects to /login.

Exports 13 API modules:
  authAPI (3 methods), courseAPI (13 methods), quizAPI (4 methods),
  assignmentAPI (4 methods), submissionAPI (6 methods), fileAPI (2 methods),
  analyticsAPI (2 methods), internalMarkAPI (4 methods), achievementAPI (4 methods),
  eventAPI (4 methods), announcementAPI (4 methods), timetableAPI (5 methods),
  syllabusAPI (5 methods), semesterCalendarAPI (4 methods),
  adminAPI (9 methods), courseMaterialAPI (5 methods)

Total: 74 API methods mapping to backend endpoints.
